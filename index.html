Arbiter

github.com/yoonbo1/arbiterai · prototype · synthetic data only

A HIPAA-oriented RAG system for clinical documents, built as a prototype and tested on synthetic records only. No real patients and no compliance claim. It has one rule, enforced in code: nothing reaches a model until the document is marked de-identified.

Documents are scrubbed with Presidio before indexing (FastAPI, Redis Streams, LangGraph, Postgres with pgvector). The map back to the original identifiers is encrypted per tenant and never enters the vector index. Row-level security sits on every table holding PHI, and cross-tenant probes prove it: during bring-up the services were connecting as the Postgres superuser, which bypasses row-level security entirely, so the policies existed and applied to nothing.

The eval harness caught its own flattering metric. Recall read 0.967 while ZIP codes survived in 14 of 20 documents, because the metric matched whole strings. A per-component metric and new recognizers took it to 1.000, and answer accuracy went from 23/40 to 38/40 in four measured iterations. Answers are rejected on an identifier leak, a missing citation, or low faithfulness, and the leak check on the way out uses the same threshold as the scrub on the way in.

Everblue

everblue.me · live on the App Store · built and operated solo

An AI journaling app. People write about their lives in it, so I treat its privacy copy as a technical claim that has to be backed by something.

The journal is stored on the phone, and so is retrieval: MiniLM embeddings through ONNX, BM25 and recency decay in SQLite. The index and the embeddings never leave the device. The companion has also run entirely on Apple’s on-device Foundation Models. What does leave, chat and photos the user adds, is listed exactly: photos pass an on-device sensitive-content check and are EXIF-stripped first, and the backend passes requests along without keeping them.

Provider data retention is account configuration, not code, so the code doesn’t pretend. A flag for zero-data-retention routing stays off until the routing is verified, and the app reads its privacy wording from a backend endpoint that reports the real posture, falling back to the cautious version.

Every prompt change goes through an eval harness that runs the production pipeline on synthetic days: a 92% bar on generation quality and 100% on no-fabrication. A companion that invents a memory is worse than no journal at all.

tickatap

tickatap.com · live · built and operated solo

A group going-out planner. The host picks a day, each friend taps what they’re into from a board of real events and places, and the plan builds itself when the last person finishes. Friends can vote on a shared night through one link, no account needed.

The board is fed by a daily curation agent. Page extraction runs on a local 14B model that I chose by measuring two candidates on the same real pages (11 clean events in 968 tokens, against 3 truncated events in 3,117 from a 26B model), so page text never leaves my machine for that step. The planner treats web text as untrusted data, and every stop the model proposes is checked in code against real records before anyone sees it.

Analytics are first-party and minimal: no user id, IP or free text, and any parameter not declared in the event schema is dropped before it reaches a third party. Under it is a TypeScript monorepo (Fastify, Next.js 15, Expo, Postgres) with 3,682 tests that run with no database, network or vendor keys.
